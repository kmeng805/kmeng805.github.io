Part 1: Fun with Filters

Convolutions from Scratch

What are convolution operations?

You can think of convolution as a sort of filter operation, where we take our kernel ("filter" matrix) and scan it across our image matrix, computing our output values along the way. The process is as follows:

  • First, we flip the filter matrix both horizontally and vertically. This is what makes the convolution operation different from just regular cross-correlation! Flipping the matrix allows the operation to be commutative and associative, which lets us apply many filters as just one aggregated filter.

  • Then, for every pixel in our image [f], we compute the cross-correlation (the dot product between local neighborhood [red box] and kernel [h] per pixel) and assign those values to our output matrix [g]. See the below visualization (taken from lecture slides)!

We can implement convolution as described above using just our basic numpy operations. Here's a potential implementation using 4 for loops: 

# manual convolution with 4 for loops
def convolve_manually_4(image, input_filter): # input image is gray

    box_r, box_c = input_filter.shape
    pad_r, pad_c = box_c // 2, box_r // 2 # pad_r means how much on left / right of every row
    filter_flip = np.flip(input_filter, 1)
    filter_flip = np.flip(filter_flip, 0)
    
    im_pad = np.pad(image, ((pad_c, pad_c), (pad_r, pad_r)), constant_values=0) # pad the image (with 0s)
    manual_4_output = np.zeros(image.shape)

    for px in range(len(image)):
        for py in range(len(image[0])):
            total = 0
            for fx in range(box_r):
                for fy in range(box_c):
                    total += filter_flip[fx][fy] * im_pad[px + fx][py + fy]
            manual_4_output[px, py] = total
    
    return manual_4_output

The above implementation is quite inefficient, since we are manually computing every individual multiplication for every pixel's neighborhood (in the two inner for loops). We can replace the two inner loops with NumPy operations instead, taking advantage of their faster vectorized operations.

Here's what the implementation could look like with two for loops:

# manual convolution with 2 for loops
def convolve_manually_2(image, input_filter): # input image is grey
    box_r, box_c = input_filter.shape
    pad_r, pad_c = box_c // 2, box_r // 2 # pad_r means how much on left / right of every row
    filter_flip = np.flip(input_filter, 1)
    filter_flip = np.flip(filter_flip, 0)
    
    im_pad = np.pad(image, ((pad_c, pad_c), (pad_r, pad_r)), constant_values=0) # pad the image (with 0s)
    
    manual_2_output = np.zeros(image.shape)
    for px in range(len(image)):
        for py in range(len(image[0])):
            matmul_sum = np.dot(np.reshape(filter_flip, box_r * box_c), 
                                np.reshape(im_pad[px:(px + box_r), py:(py + box_c)], box_r * box_c))
            manual_2_output[px, py] = matmul_sum
    
    return manual_2_output

scipy also has a nice built-in function we can use to convolve matrices together (scipy.signal.convolve2d). Unlike our bare implementations above, the convolve2d function is much more flexible:

  • The mode parameter allows us to determine the shape of the output image (e.g. if we only convolve for pixels that have enough neighbors, our output will shrink $\rightarrow$ mode='valid'). In our functions, we maintain the same shape for the output.

  • The boundary parameter allows us to determine how we pad our image, which will allow us to perform the convolution for pixels near the border as well (i.e. make the dimensions of the local neighborhood match the dimensions of the kernel). In our functions, we pad with a fixed value (zero).

  • The fillvalue parameter allows us to determine what fixed value to pad our image with. In our functions, we pad with zero.

  • Read the documentation for more!

scipy.signal.convolve2d is also better runtime-wise, since it performs more optimizations under the hood (in contrast to our two outer for loops, where we're manually going through every pixel).

Part 2: Fun with Frequencies

Image "Sharpening"

For those who don't have the new iPhone 23847 Pro Max, don't you sometimes wish that your camera quality was better? Introducing image "sharpening"!

Images consist of low and high frequencies: lower frequencies correspond to more broad changes within an image, and higher frequencies correspond to the fine details within an image. To sharpen our image, we can extract these high frequencies, then add a multiple ( $ >1$) of them back to the original image, artificially increasing the details within an image. If we want more details, we increase this multiple, but increasing it too much can make our image look too unrealistic (see below).

To extract the high frequencies, we can use a high-pass filter. Or, we can use a low-pass filter, and subtract the results of the low-pass filter from the original image to obtain the high frequencies. We'll do the latter, since the Gaussian kernel is a perfect low-pass filter.

Here's the equation describing the image sharpening process, where $I_S$ is the sharpened image.

$I_S = I + cI_H = I + c(I - I_L) = I + c (I - GaussConv(I))$

Hybrid Images

We can also manipulate the frequencies of images to create hybrid images! Hybrid images are images that show different figures depending on how far the viewer is. To do so, we'll start with two images:

  • We'll designate Image 1 as the image that's seen when the viewer is close. Being closer allows the viewer to perceive higher frequencies, so we want Image 1 to consist of higher frequencies. We'll use our tactic earlier of subtracting the low-pass result from the image to obtain the high-pass result. The threshold for our "higher" frequencies is determined through experimentation.

  • We'll designate Image 2 as the image that's seen when the viewer is far. Being far means the viewer will be better at perceiving lower frequencies, so we want Image 2 to consist of lower frequencies. We'll use our handy dandy Gaussian filter. Again, the threshold for our "lower" frequencies is determined through experimentation.

  • We'll combine Image 1 and Image 2, again with some experimentation. We could directly add them together, but the results didn't look so nice. Instead, we multiplied each of the images by a constant, then added those together, and that made the final image much nicer to look at!

Gaussian and Laplacian Stacking

What if we want to blend images? The naive way would be just to paste them together. If we try to blend an apple and orange this way...

Yikes!

We'll see how we can improve this using Gaussian and Laplacian stacking!

  • First, we must make a Gaussian stack per image, where each level of the stack is the original image convolved with a Gaussian filter, who's dimensions and sigma increase as we go down the stack. In essence, we are getting the lowest frequencies, then the next lowest, etc. We'll also do this with our mask.

  • Why did we make the Gaussian stack? We're actually going to use our Gaussian stack to make our Laplacian stack, which we will use for the blending. Recall that the Laplacian (high-pass) can be found by just subtracting the Gaussian (low-pass) from the original. From our Gaussian stack, we'll get each level of the Laplacian stack by subtracting the $(i+1)^{th}$ Gaussian level from the $(i)^{th}$ Gaussian level. Our Laplacian stack gives us the highest frequencies, then the next highest, etc.

  • Once we have our Laplacian stacks from our two images, we can apply our mask (a Gaussian stack) to each level. We'll apply the binary mask (first level of our Gaussian stack) to our highest frequencies, the next mask (second level of our Gaussian stack) to our next-highest frequencies, etc. This ensures that we get a smoother blend for the lower frequencies, and more of a concatenation for our higher frequencies (we don't want to lose detail).

  • Once we're done, we add up all the levels of our Laplacian (+ the lowest level of the Gaussian; think about why!), and we get our reconstructed image.
